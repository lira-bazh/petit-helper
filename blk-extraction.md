# Распаковка BLK Petit Planet

В проекте есть проверенный распаковщик: `scripts/unpack-blk.mts`.
Он извлекает файлы из контейнеров `PetitPlanet_Data/StreamingAssets/AssetBundle/blocks/**.blk`.
Поддерживаются несколько последовательно записанных Unity-бандлов в одном BLK.

Скрипт читает игровые файлы, расшифровывает заголовки и сжатые блоки, распаковывает LZ4
и записывает результат в отдельный новый каталог. `UnityPlayer.dll` используется только
как источник таблиц: DLL не загружается и её машинный код не исполняется.
Дополнительные пакеты не нужны.

## Проверенная версия

Проверено на локальном клиенте `live_0.95`, revision `1217551`, 9 октября 2026 года,
с Node.js `v24.16.0` в WSL. Скрипт требует Node.js с поддержкой запуска TypeScript `.mts`.

SHA-256 поддерживаемого `UnityPlayer.dll`:

```text
b28d3cb0990cec4366704aa21d448aa3464cd2a6c6afe1b226fadc71a794d7a8
```

Скрипт проверяет этот хеш перед расшифровкой. После обновления игры расположение таблиц
нужно исследовать заново; удалять проверку хеша без проверки алгоритма нельзя считать
поддержкой новой версии.

## Запуск

Выполнять из корня проекта `/home/lira/dev/petit-helper`.
Windows-путь `F:\GAMES\PetitPlanet Game` в этой WSL-среде доступен как
`/mnt/f/GAMES/PetitPlanet Game`.

```sh
pnpm exec node scripts/unpack-blk.mts \
  '/mnt/f/GAMES/PetitPlanet Game' \
  '/mnt/f/GAMES/PetitPlanet Game/PetitPlanet_Data/StreamingAssets/AssetBundle/blocks/00/00000001.blk' \
  /tmp/petitplanet-example-00000001
```

Аргументы по порядку: каталог игры, конкретный BLK, новый каталог результата.
Родитель каталога результата должен существовать. Сам каталог результата должен
отсутствовать: скрипт не перезаписывает предыдущую выгрузку и не разрешает выгрузку
внутрь каталога игры. Для повторного запуска выберите другое имя каталога.

Пример файла с несколькими бандлами:

```sh
pnpm exec node scripts/unpack-blk.mts \
  '/mnt/f/GAMES/PetitPlanet Game' \
  '/mnt/f/GAMES/PetitPlanet Game/PetitPlanet_Data/StreamingAssets/AssetBundle/blocks/00/00001506.blk' \
  /tmp/petitplanet-example-00001506
```

## Результат

```text
petitplanet-example-00000001/
  manifest.json
  00000000/
    CAB-a4288937deecd9d8b05dbee3349fe97b
    CAB-a4288937deecd9d8b05dbee3349fe97b.resS
```

Название подкаталога — шестнадцатеричное смещение начала бандла внутри исходного BLK.
Это позволяет сохранить несколько бандлов и не смешивать их файлы.

`manifest.json` записывается после успешной распаковки всего BLK. В нём находятся:

- путь и SHA-256 исходного файла;
- SHA-256 использованного `UnityPlayer.dll`;
- смещения и размеры бандлов;
- размеры и флаги сжатых блоков;
- имена, пути, размеры, флаги и SHA-256 извлечённых файлов.

Если команда завершилась ошибкой, каталог может содержать уже извлечённые бандлы.
Такая выгрузка не считается полной: итогового манифеста в ней нет.

## Что именно извлечено

`CAB-*` — сериализованный файл Unity. `.resS` — сопутствующие двоичные ресурсы.
Их нужно хранить вместе. Распаковка контейнера не превращает объекты Unity автоматически
в JSON, изображения или отдельные `TextAsset`.

В проверенных CAB-файлах заголовок сериализации имеет версию `22`, а строка Unity —
`2022.3.43f1`. Размер файла, записанный в расширенном заголовке Unity, совпадает
с фактическим размером извлечённого файла.

Для поиска `FlowerDropCfg.bytes` и `FlowerPointPoolCfg.bytes` следующий этап — разбор
объектов внутри CAB и извлечение соответствующих `TextAsset`. Совместимость конкретного
внешнего редактора Unity-ресурсов с этими объектами здесь не проверялась.
`src/lib/flowers.json` распаковщик не изменяет.

## Отличие от `AssetBundle/0.blk`

`PetitPlanet_Data/StreamingAssets/AssetBundle/0.blk` — отдельный индекс ресурсов.
Его формат отличается от контейнеров в `AssetBundle/blocks/`; этот скрипт его
не распаковывает и завершится сообщением о неподдерживаемом формате.
Не нужно переименовывать индекс или подставлять его вместо архива с ресурсами.

## Как устроена распаковка

Для проверенного формата последовательность следующая:

1. Проверяется сигнатура `c3 9c c3 a3 c3 8a 00` и версия заголовка `0`.
2. Из восьми байтов после версии составляются параметры расшифровки заголовка.
3. Расшифровываются 32 байта заголовка: проверяются размер бандла, размеры метаданных
   и флаги. Начало метаданных находится на смещении 64 от начала бандла.
4. Метаданные расшифровываются и распаковываются. Они содержат каталог файлов
   и список сжатых блоков.
5. Начало данных выравнивается на 16 байтов после метаданных. Типы сжатия `2` и `3`
   читаются как LZ4, тип `5` сначала расшифровывается, затем читается как LZ4.
6. Распакованные блоки объединяются, а файлы извлекаются по диапазонам из каталога.
7. Обработка продолжается со следующего бандла, пропуская нулевое заполнение.

Расшифровка сочетает AES-128-ECB для первых 16 байтов, преобразование остальных байтов
потоком с перестановкой состояния и три раунда преобразования первых 16 байтов.
Таблицы для этой версии читаются из секций PE по фиксированным RVA. Сам алгоритм
реализован на TypeScript; исследовательские временные файлы из `/tmp` для запуска
не нужны.

## Ограничения и проверка

Поддержаны несжатые блоки и типы сжатия `2`, `3`, `5`. LZMA и другие типы не реализованы.
Метаданные в конце бандла и заголовки без выравнивания отклоняются.
Предел распакованного блока — 256 MiB, одного бандла — 1 GiB.
Исходный BLK и текущий распакованный бандл читаются в память.

Проверенные файлы:

| BLK | Бандлов | Извлечённых файлов | Распаковано, байт |
| --- | ---: | ---: | ---: |
| `00000001.blk` | 1 | 2 | 2 345 095 |
| `00001506.blk` | 116 | 166 | 31 216 074 |
| `00006251.blk` | 91 | 182 | 13 478 616 |

Всего проверено 208 бандлов и 350 файлов. Для всех сериализованных файлов из этих
выгрузок проверено совпадение размера из заголовка Unity с размером на диске.
Заголовок и метаданные первого BLK также побайтно сверены с первоначальной
исследовательской расшифровкой.

Контроль после изменения скрипта:

```sh
pnpm lint
pnpm exec tsc --noEmit --incremental false
```

Повторите распаковку одного одиночного и одного составного BLK в новые каталоги,
затем сравните размеры и SHA-256 файлов с манифестами предыдущей проверенной выгрузки.
